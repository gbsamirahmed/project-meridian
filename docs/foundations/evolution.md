# Meridian subsystem evolution register

Reviewed 9 October 2026. **F33** records an evidence-led evolution policy, not a replacement implementation programme. Stable concepts and scientific authority survive implementation changes. Read [platform options](platform.md), [decisions](decisions.md) and [documentation precedence](reconciliation.md#documentation-precedence) together.

The register separates existing implementation from proposals. No national-scale capacity follows from the retained pilots. Before a revisit, record the workload, hardware/software, distributions, storage and failure behaviour against a declared user/operational requirement. Candidate counts alone are not end-to-end performance. Agree numerical thresholds only when the workload is known; no scaling trigger below authorises work by itself.

## Evolution discipline

One short decision update should state the demonstrated limitation, alternatives, migration/conformance evidence, preservation/rollback plan and authorised scope. Expensive schema, authority or published-client changes warrant an ADR under [engineering](engineering.md); an internal renderer or index improvement may only need a measured decision note. Record supersession explicitly; keep historical reports and negative findings.

Full Atlas validation remains the default. Current local process-interruption results do not establish power-loss or distributed durability. No subsystem register entry reopens closed receipt optimisation or authorises changing scientific contracts. Weather owns its own acquisition and publication; rendering products and offline projections never redefine source meaning. See [economics](economics.md) before any public-exposure architecture and the [roadmap](roadmap.md) for stage-specific compatibility.
